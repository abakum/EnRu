# Отчёт: переключение раскладки в Microsoft Word

**Результат:** пользователь подтвердил, что прототип EnRu с системными сочетаниями переключал раскладку в Word без зависания на Windows 10 (сборка 14393, amd64). Переключатель вынесен в `cmd/c1c2`. Для `c1c2` пользователь отдельно подтвердил, что переключение с панели задач через `Progman` работает.

## Что проверили

- Прямой `WM_INPUTLANGCHANGEREQUEST` в IME-окно по схеме FluentSwitcher несколько раз сработал, но затем Word завис. Смена адресата не устранила зависание; точная причина не установлена.
- Обход через `Progman` сообщал об успехе, но менял раскладку рабочего стола, а не Word.
- Системные сочетания для конкретных раскладок (`Ctrl+1` для EN и `Ctrl+2` для RU) работали в Word вручную, а затем и при вызове из EnRu.

## Текущая реализация

- Экспериментальные изменения в основном EnRu откатили. В `cmd/c1c2/for_windows.go` одиночный левый `Ctrl` отправляет `Ctrl+1`, правый отправляет `Ctrl+2` через `SendInput` во всех приложениях. Раскладки для этих сочетаний задаёт Windows, а не `c1c2`. Прямых запросов `WM_INPUTLANGCHANGEREQUEST` из `c1c2` нет.
- При фокусе на панели задач (`Shell_TrayWnd`, `Shell_SecondaryTrayWnd` или подсказка `tooltips_class32`) `c1c2` активирует `Progman` и отправляет сочетание только после подтверждения фокуса. Это не прежний обход для Word: `Progman` используется только при старте переключения с панели задач. Вариант с активацией ближайшего приложения оказался нестабильным и был заменён.
- `c1c2` сохраняет команды `install`, `start`, `uninstall`, `stop`, `console`, запуск в фоне и звуковые сигналы. Сообщения на английском; ярлык автозагрузки `c1c2.lnk` отдельный. `make c1c2` собирает `c1c2.exe` с иконкой, Windows-манифестом и английскими метаданными версии.

Кросс-сборки Windows `amd64` и `386` прошли. Успешный `SendInput` подтверждает отправку сочетания, но не подтверждает раскладку каждого окна после смены фокуса.
