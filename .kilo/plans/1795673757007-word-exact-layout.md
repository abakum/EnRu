# Точный выбор раскладки в Word

## Цель

На Windows левый Ctrl выбирает EN, правый Ctrl выбирает RU, даже если установлено больше двух раскладок. Не эмулировать Win+Space: он меняет раскладку по кругу. Проверить адресацию FluentSwitcher для Word, не ломая рабочий обход через Progman. Причина прежнего зависания не установлена; другой HWND не гарантирует, что оно исчезнет.

## Изменение

1. Менять только `cmd/EnRu/for_windows.go`. Сохранить получение целевого HKL из `layoutID` и существующий путь `switchLanguage` для остальных окон. В начале ветки `OpusApp` добавить диагностический режим `ENRU_WORD_DIRECT=1`; без него оставить Progman без изменений. Переменная наследуется при запуске процесса, менять автозагрузку и общую CLI не нужно.
2. В диагностическом режиме получить ID потока исходного окна Word через `GetWindowThreadProcessId`, затем его `hwndFocus` через `GetGUIThreadInfo`. Описать структуру `GUITHREADINFO` с Win32-размерами: два `uint32`, шесть `uintptr` для HWND и прямоугольник из четырёх `int32`; заполнить `cbSize` через `unsafe.Sizeof`. Выбрать `ImmGetDefaultIMEWnd(hwndFocus)`, как во [FluentSwitcher](https://github.com/DmitryN71/FluentSwitcher/blob/eb4f015f32e45a02d41a27c34a8b8f3d1c7547d6/src/libtools/utils/layout-utils.h); если IME-окна нет, использовать `hwndFocus`.
3. Перед отправкой убедиться, что активным осталось исходное окно, а фокус принадлежит ему (само окно или его потомок). Не отправлять запрос самому `OpusApp` как запасному адресату. Если фокус не найден, адресат непригоден или поток адресата неизвестен, вывести причину и завершить пробную попытку. Если раскладка потока адресата уже равна целевому HKL, ничего не отправлять.
4. Отправить один `PostMessageW(WM_INPUTLANGCHANGEREQUEST, 0, hkl)` выбранному HWND; проверить результат вызова. Коротким ограниченным опросом (например, каждые 5 мс до 40 мс) проверить равенство HKL у того же потока. При смене активного окна прекратить проверку; при таймауте сообщить, что смена не подтверждена, а не что Word отклонил запрос. В пробном режиме не менять фокус, не обходить соседние окна и не запускать Progman автоматически: запрос уже мог встать в очередь, а второй путь исказит наблюдение. Логировать класс адресата и итоги в `console`.

## Проверка и откат

- Проверить сборку Windows amd64 и 386 (`GOOS=windows GOARCH=... CGO_ENABLED=0 go build ./cmd/EnRu`, выходные файлы вне рабочего дерева). Это проверяет компиляцию, не вызовы Win32 или совместимость с Word.
- В PowerShell запустить `$env:ENRU_WORD_DIRECT = '1'`, затем `.\EnRu.exe console`. На пустом документе проверить одиночные левый и правый Ctrl из обеих раскладок, повторное нажатие для уже выбранной раскладки и ввод букв после каждой смены. Повторить с третьей установленной раскладкой. Проверить отзывчивость Word, сохранение фокуса и отсутствие изменений в других приложениях.
- Если Word зависает, прекратить эксперимент. Завершить тестовый EnRu, выполнить `Remove-Item Env:ENRU_WORD_DIRECT` и снова запустить EnRu: вернётся прежний путь через Progman. Делать новый путь поведением по умолчанию только после ручной проверки на Windows; это не входит в текущую правку.
